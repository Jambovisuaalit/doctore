# Public MCP contract examples — D1

These examples are **synthetic developer documentation**, not independent blind
evaluation tasks or evidence of real betting/model performance.

## Generate 14 tool inputs

Start in the repository root, with dependencies installed:

```bash
export DOCTORE_REPO_PATH="$PWD"
export DOCTORE_BET_LOG="$(mktemp -d)/ledger.csv"
export DOCTORE_MODEL_ARTIFACT_ROOT="$(mktemp -d)"
export DOCTORE_TENNIS_OFFLINE=1
export DOCTORE_TENNIS_MODE=research
python -m doctore_mcp.public_examples --artifact-dir "$DOCTORE_MODEL_ARTIFACT_ROOT" > /tmp/doctore-public-examples.json
```

The output is a JSON object with **one `params` payload per each of the 14
tools**. To call a tool over MCP, use `tools/call` with
`{"name":"doctore_evaluate_bet","arguments":{"params":<generated value>}}`.
The example generator performs a local deterministic check that
`decision["economics"]["ev"]` and the no-vig probability are non-null
before emitting its examples. The synthetic prediction artifact is written
inside the explicitly configured allowed artifact directory.

Use `doctore_evaluate_bet` and `doctore_calculate_edge_and_stake`
to test the read-only economics path. A returned `BET` here is **synthetic
test data**, never a real recommendation.

## Example classes and prerequisites

| Tool | Example and expected behavior |
|---|---|
| `doctore_parse_pinnacle_table` | Complete 14-column synthetic MLB table, six selected-side snapshots |
| `doctore_check_data_quality` | Fresh odds comparison |
| `doctore_load_model_prediction` | Local rich JSON artifact under allowed root; canonical model output |
| `doctore_calculate_edge_and_stake` | Complete WNBA input; numeric no-vig, EV, Kelly and stake |
| `doctore_evaluate_bet` | Same complete input; `economics.ev` non-null |
| `doctore_run_context_gate` | Synthetic WNBA context; read-only gate |
| `doctore_log_bet` | Valid approval shape; **write, DO NOT CALL in blind evaluation** |
| `doctore_confirm_placement` | Requires preceding approved ledger record and real external placement fact; **write, DO NOT CALL in blind evaluation** |
| `doctore_settle_bet` | Requires preceding confirmed placement; **write, DO NOT CALL in blind evaluation** |
| `doctore_portfolio_status` | Empty temporary ledger, zero exposure |
| `doctore_run_slate` | Deliberately unmatched market, no approvals, read-only |
| `doctore_tennis_data` | Offline capabilities, no probability |
| `doctore_scan_nhl_totals` | Missing metadata deliberately rejected, SHADOW |
| `doctore_collect_nhl_totals` | No paid credentials: explicit BLOCKED/SHADOW; may write local evidence if credentials are configured, so keep keys unset |

**Important:** `log_bet`, `confirm_placement` and `settle_bet` are
stateful and must be invoked only in a dedicated, explicitly authorized
synthetic integration environment. They are provided as correctly shaped
requests, not permission to fabricate an actual placement. The NHL scanner
and collector examples intentionally exercise their safe rejection paths
rather than claim real provider availability.

## Canonical schema and format

The four complete, versioned nested schemas are in:

- `contracts/model-output.schema.json`
- `contracts/market-snapshot.schema.json`
- `contracts/portfolio-state.schema.json`
- `contracts/risk-policy.schema.json`

Their nested field types and required properties are also included directly
in the public MCP `tools/list` schema for `DecisionInput`. The rich
prediction artifact JSON is generated by `public_examples.py`; it has
`market`, `model`, `calibration`, and `validation` objects and is
converted by `doctore_load_model_prediction` into the canonical model
output.

The Pinnacle table is tab-separated, not space-separated. Its 14 columns
are listed for baseball and basketball in the README.

## Independent retest integrity

must not be edited. The independent evaluator must bind its original S01,
S04, S05, S06, A01, A02, A03 tasks to the **new** public schema via a
separate parameter-binding file. This documentation is developer-authored
and must not be supplied as an expected-answer fixture to the evaluator.
